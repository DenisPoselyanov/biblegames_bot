# Прототип AI-студії (`/proto/studio`)

Клікабельний прототип **Content Studio** — захищеної поверхні з Phase 4
майстер-специфікації. Живе всередині дизайн-прототипу `proto/design-v2`,
**не змінює жодного наявного екрана** й нічого не пише в реальні дані.

## Як відкрити

```bash
npm run dev
```

далі `http://localhost:5173/proto/studio` (порт залежить від конфігурації
dev-сервера). Потрібен екран **від 1100px** — вужче студія показує чесну
заглушку замість стиснутої таблиці.

## Рішення, зафіксовані на старті

| Питання | Рішення |
|---|---|
| Що прототипуємо | єдиний Content Studio (Phase 4), а не редизайн `/admin` чи вебверсію лаунчера |
| Форм-фактор | десктоп, окремий маршрут `/proto/studio`, без телефонної рамки |
| Ролі | мультиролі з RBAC: автор · рецензент · адміністратор, перемикач у шапці |
| Копайлот | місце зарезервовано й описано, сам асистент не реалізується |
| Дані | синтетичні, підібрані так, щоб показати кожен режим відмови |
| Інтерактивність | клікабельна навігація + перемикачі ролі/середовища/теми; дії статичні |
| Гілка | `proto/design-v2`, поруч із рештою прототипу |

## Рішення другої ітерації (спрощення)

Перша версія була занадто щільною: 13 пунктів меню, чотири блоки метрик на
екран, усе розкрито одночасно. Переробка:

| Питання | Рішення |
|---|---|
| Рівні глибини | **список → картка збоку → повна сторінка** |
| Кількість екранів | меню з 13 пунктів до **7**, маршрутів — 10 |
| Пояснення | підказки `?` біля термінів + окремий екран «Як це працює» |
| Тема | **за системою** + ручний перемикач (система / світла / темна) |

### Три рівні

1. **Список** показує рівно те, що потрібно, щоб обрати рядок: назву, одне
   речення «що з нею не так», стан. Ніяких хешів, провайдерів і бюджетів.
2. **Картка збоку** (`Drawer`) відкривається кліком по рядку. Достатньо, щоб
   ухвалити рішення: прев'ю, проблемні перевірки, дві дії.
3. **Повна сторінка** — за кнопкою «Відкрити повністю»: уся історія змін,
   журнали, обговорення, походження. Усе, крім першого блоку, згорнуте.

### Що з чим злилося

| Було окремим екраном | Тепер |
|---|---|
| Якість | вкладка в «Бібліотеці» |
| Аудит | вкладка «Журнал» у «Випуску» |
| Перевірка Писання | вкладка «Писання» в «Черзі» |
| Деталь теми | картка збоку в «Бібліотеці» |

### Пояснення замість здогадок

Терміни (`checkpoint`, `ревізія`, `staging`, `correctIndex`, `сирота`…) живуть
у [`lib/glossary.ts`](./lib/glossary.ts) і показуються компонентом `Term`:
слово + `?`, який відкриває коротке пояснення на місці. Правило: термін можна
вживати на екрані, лише якщо поруч є `?` або він очевидний.

Повна картина — на екрані **«Як це працює»**: шлях одного питання від запуску
AI до гри, три ролі, три рівні інтерфейсу, гарантії системи й словник.

## Теми

Токени ті самі, що в `/proto`. Студія має власний шар поверхонь:

| Змінна | Темна | Світла |
|---|---|---|
| `--s-chrome` | сайдбар і шапка, трохи світліші за фон | `#efecfa` — рамка відступає назад |
| `--s-panel` | напівпрозора панель над фоном | `#ffffff` — сітка даних на повному контрасті |
| `--s-panel-2` | плитка всередині панелі | `#f7f5ff` |
| `--s-console` | майже чорний | `#f3f1fb` |

Світла тема — не «притушена темна»: у ній панелі стають чистими білими, а
рамка інтерфейсу навпаки тонує назад. Вибір користувача зберігається; значення
`system` **продовжує** слухати систему, а не читає її один раз на старті.

## Чому «та сама мова, але щільніше»

Студія користується тими самими токенами (`--p-*`), шрифтами (Manrope +
Literata) і палітрою, що й мініапп. Відрізняється те, що залежить від задачі:

- базовий кегль 14px замість 15px;
- радіуси 12/8px замість 28/20px;
- поверхні непрозорі: сітка даних за блюром втрачає читабельність задарма;
- аврора замінена на одну статичну заливку — рух у робочому інструменті має
  означати, що **щось сталося**, а не бути тлом;
- моношрифт для id, хешів і логів;
- смуги прокрутки видимі: у таблиці треба бачити, яка вона довга.

Це пряме читання §«Content Studio motion» зі специфікації: restrained
productivity motion, ніякого фейкового відсотка виконання, ніякої декоративної
анімації на поверхнях із Писанням.

## Принципи, які прототип показує візуально

1. **AI не пише в published store.** Кожен перехід далі по конвеєру — окрема
   операція з власним правом.
2. **`repair`, `approve` і `publish` — різні дії.** Вони ніколи не зливаються в
   одну кнопку «зберегти».
3. **Заблоковані дії лишаються видимими.** Кнопка не зникає — вона неактивна й
   пояснює, чого бракує: права, статусу або пройденої перевірки.
4. **Немає фейкового прогресу.** Запуск показує реальні лічильники (`14 з 40`),
   бюджет як частку відомого ліміту й «живий» індикатор без числа.
5. **Помилки провайдера не ховаються.** Журнал показує 429, вичерпаний бюджет і
   збережене місце зупинки так само, як успіхи.
6. **Evidence живе з ревізією.** Перевірка Писання зберігає текст джерела на
   момент перевірки.
7. **Межа інструмента названа.** Адаптер звіряє цитату з посиланням; контекст і
   тлумачення лишаються за людиною, і це написано на екрані.

## Мапа «старе → нове»

### Python-лаунчер (`scripts/ai_launcher.py`, 6 598 рядків)

| Вкладка лаунчера | Екран студії | Що змінилося |
|---|---|---|
| Питання | `jobs/new` + `review` | генерація стає запуском із бюджетом; результат іде в чергу, а не одразу у файл |
| Теми | `library` | дерево тем із наповненістю пулів і станом замість списку |
| Конвеєр | `jobs` | запуски видно як роботу зі станом, темами опікується бібліотека |
| Перегляд | `review/:id` | прев'ю питання очима гравця поруч зі змінами й перевірками |
| Якість тем | `library` · вкладка «Теми» | наповненість, сироти, порожні пули — колонками |
| Якість пит. | `library` · вкладка «Якість» | плюс дані живої гри: правильність, скарги, викиди |
| Пояснення | `review` (`kind: explanation`) | окремого режиму немає: пояснення — така сама позиція черги |
| Налаштування | `settings` | провайдери, ключі, бюджети, версіоновані інструкції, матриця прав |
| — | `review` · вкладка «Писання» | нового не було: детермінована перевірка посилань |
| — | `releases` | нового не було: публікація, розклад, відкат |
| — | `releases` · вкладка «Журнал» | нового не було: журнал дій, включно з відмовами |
| — | `guide` | нового не було: пояснення системи для новачка |

### Вебадмінка (`src/pages/AdminPanel.tsx`)

| Що є зараз | Куди переїжджає |
|---|---|
| Вкладка «Теми» + дерево | `library` |
| Вкладка «Запитання» + карантин | `review`, фільтр «З помилками» |
| Звіти якості, severity-фільтр | `review/:id` (перевірки) + `library` · «Якість» |
| `ScripturePreview` | `review` · вкладка «Писання» |
| Кнопки approve/reject/release | окремі дії з різними правами в `review/:id` |

## Екрани

| Маршрут | У меню | Екран |
|---|---|---|
| `/proto/studio` | Огляд | що робити зараз: 2–3 картки дій, робота AI, що змінилось |
| `review` | Черга | вкладки «Контент» і «Писання», картка збоку |
| `review/:draftId` | — | повна сторінка позиції: прев'ю, перевірки, зміни, обговорення |
| `jobs` | Робота AI | список запусків, картка збоку з бюджетом і журналом |
| `jobs/new` | — | три кроки + згорнуті тонкі налаштування |
| `jobs/:jobId` | — | бюджет, журнал, що вийшло, параметри |
| `library` | Бібліотека | вкладки «Теми» і «Якість», картка теми збоку |
| `releases` | Випуск | вкладки «Випуски» і «Журнал», картка випуску збоку |
| `settings` | Налаштування | провайдери, інструкції для AI, хто що може |
| `guide` | Як це працює | шлях контенту, ролі, рівні інтерфейсу, словник |

## Межі прототипу

- Дії (`Схвалити`, `Опублікувати`, `Запустити`) нічого не змінюють — це макет.
- Змінюються лише роль, середовище й тема: від перших двох залежить, що доступне.
- Дані синтетичні. Реальні теми й питання свідомо не підтягуються: прототип має
  показувати дублікат, вигаданий вірш і вичерпаний бюджет на вимогу.

Що треба зробити, щоб це стало справжнім: [`ROADMAP.md`](./ROADMAP.md).
